# Viva guide: what you must be able to explain, reproduce and change

The brief says a short verification discussion may ask you to explain a function, reproduce a test and make one small change. Prepare these.

## Explain
1. **FE assembly** (`thermal.cpp: assemble`): each element adds `kA/h [[1,-1],[-1,1]]` to K and `qAh/2` to both load entries; the global matrix is tridiagonal.
2. **Boundary conditions** (`applyDirichlet`): move the known T(0) and T(L) to the right-hand side of the neighbouring rows, then make the two end rows identity rows.
3. **Thomas algorithm** (`solveTridiagonal`): forward elimination then back substitution, O(N); a tiny pivot means a singular system.
4. **Why error at midpoints**: nodal values are exact for this problem (1e-13); the interpolation error at a midpoint is q h^2/(8k), which gives 1.25, 0.3125, 0.0781, 0.0195 C and order 2.
5. **Parallel batch** (`batch.cpp: runParallel`): atomic counter hands out case indices; each case writes its own slice, so no locks are needed on results; per-thread scratch buffers; results stay in input order; same `solveInto` as serial.
6. **Speedup and efficiency**: speedup = T1/Tp, efficiency = speedup/p; reasons for less-than-ideal scaling (thread start, queue contention, small work, memory bandwidth, hyper-threads).
7. **Backpropagation** (`backprop.cpp`): the 8 chain-rule lines in `docs/worksheet_to_copy_by_hand.pdf`; why the update is simultaneous; why central differences have error O(eps^2) and agree to 1e-10.
8. **JTAG adapter vs compute board**: fixed-function protocol translator with target-referenced buffers (Vref), vendor tool support, no user logic.
9. **STL/CSV validation**: what is rejected and why (non-finite, malformed, duplicate IDs, binary STL).

## Reproduce
```
ctest --test-dir build --output-on-failure
./build/aether_results results
```
Open the Performance page and run the benchmark; open the Verification page and run the self-checks.

## Likely small changes to practise
- Change the heat generation to q = 20000 and predict the midpoint error at N = 10 (answer: 2.5 C) before running it.
- Change the learning rate to 0.5 and watch the loss curve.
- Add a new STL rejection rule or a new test case (copy an existing test in `tests/test_stl.cpp`).
- Make the worker counts 1, 2, 4 in `BenchmarkConfig`.
